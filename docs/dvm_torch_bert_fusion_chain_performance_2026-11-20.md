# dvm-torch BERT BS256 与 BS512 成图算子链性能统计

文档日期：2026-11-20。实验数据日期：2026-11-19。

本文件记录 emit 优化前的基线。后续 `neg`、常量除法和广播 shape 推导优化的实现及复测结果，见 [emit 性能优化验证](../output/benchmarks/emit_optimization_2026-11-20/report.md)。

当前优化后版本的全部算子链与同期原生 Device 耗时对照，见[优化后算子链性能统计](dvm_torch_bert_fusion_chain_performance_after_emit_2026-11-20.md)。

BERT 完整训练在 BS256/512 下，每步均生成 **316 张图**，覆盖 1000 个算子，执行 520 个 DVM kernel。按算子序列、shape、依赖关系和实际输出区分，共 **18 类图**。

**统计口径更正（2026-11-20）：初版只统计了 kernel，漏计了原生算子内部的 GPU memcpy 和 memset。初版的“整体慢约 8.2%”和“attention mask 链是最大的劣化来源”不适用于完整 Device 耗时。以下表格和结论均已补齐这些事件。**

这些图对应的完整 GPU 工作，合计比原生慢约 **0.35% / 0.38%**：

| Batch size | 原生 GPU 耗时 | DVM GPU 耗时 | 增加耗时 | 变化 |
|---|---:|---:|---:|---:|
| 256 | 245.741 ms | 246.596 ms | +0.855 ms | +0.35% |
| 512 | 485.834 ms | 487.659 ms | +1.825 ms | +0.38% |

原生每步额外执行的 36 次 `masked_fill → clone → copy_` 设备拷贝，累计耗时 **17.701 / 35.318 ms**；36 次被融合的 reduction 初始化 memset 另占 **0.054 / 0.054 ms**。DVM 消除了这些事件。只看 kernel 时的 227.986 / 450.462 ms 不包含这些原生开销。

实验使用 TorchBench 的 `BERT_pytorch` 完整训练，GPU 为 Tesla V100-PCIE-32GB，精度为 FP32，序列长度为 128，hidden size 为 768，词表大小为 20032。12 层 Transformer 使用非重入 activation checkpoint，优化器和 loss 布局沿用原始 Adam 与 NLLLoss。开启 sum 融合，但禁止独立 sum 成图。

耗时来自完整训练中未插桩的生产 trace，取 **3 步平均的 GPU kernel、memcpy、memset 时间之和**。比较范围是被这些图替换的原生 GPU 工作，不包含 CPU 机制开销，也不是整步训练耗时。诊断插桩只用于识别图结构和算子归属；诊断与生产 trace 的 kernel 名称、grid、block、shared memory 和寄存器数量均已逐一匹配。

内存事件通过 CUDA correlation、CPU 算子调用层级和出现次序归属到对应算子。每步 72 个被替换的原生内存事件均已归图；其余内存事件在原生和 DVM 之间按调用身份、类型、顺序和字节数逐一匹配。DVM 图没有额外的 memcpy/memset 事件。整步 GPU 事件耗时之和与时间区间并集之差小于 0.001 ms，因此这些 trace 不存在影响上述累计结果的并发重叠。该验证比初版仅验证 kernel 的范围更完整。

- `H = [B,128,768]`；attention 数据为 `[B,12,128,128]`，mask 为 `[B,1,128,128]`。
- `N5 = sub, mul, add, div, add`，对应 LayerNorm 的归一化与仿射计算。
- `B9 = div, div, neg, mul, div, sum, mul, mul, sum`，对应 LayerNorm 反向。
- 序列表示捕获顺序，图内可以有分支；“独立”表示两个算子没有数据依赖。

从完整清单可以得到以下结论。下文成对列出的耗时分别对应 BS256 和 BS512。

1. **收益主要集中在 C04、C11、C12。**这三类共 72 张图，每步节省 **16.170 / 31.452 ms**。C06 的差异仅约 0.3%，可视为基本持平。

2. **std 反向 C14 是最大的单类劣化来源**，每步增加 **7.858 / 15.618 ms**。attention mask 的 C05、C10、C16 合计反而节省 **0.736 / 1.070 ms**；其中前向和反向略有收益，保存 mask 的重计算链仍慢约 3%～4%。初版对 attention mask 的劣化判断由漏计原生 clone 拷贝造成。

3. **同一算子序列，保存的输出不同，收益差别很大。**N5 前向只保存最终结果，快约 16%～17%；重计算需要保存 4 个输出，基本没有收益。因此不能只按算子名称和链长判断融合效果。

4. **88 张单算子图全部变慢**，合计增加 **5.999 / 11.441 ms**。其中独立 `mean` 从 1 个 kernel 拆成 2 个，耗时增加约 76%～79%。

5. **12 张图没有形成实际的数据依赖融合。**C08/C18 的 `add/add_` 与 `mean` 使用独立输入，合图后从 2 个 kernel 变成 3 个，每步增加 **1.878 / 3.571 ms**。这是成图策略值得单独处理的一类。

统计范围限于上述 BERT 工作负载实际生成的图，不代表 dvm-torch 支持的全部算子。每步图大小分布为：1 算子图 88 张、2 算子图 84 张、3 算子图 24 张、4 算子图 24 张、5 算子图 72 张、9 算子图 24 张。合计 88 张单算子图和 228 张多算子图。

整步耗时与上述算子链耗时的关系如下。第一至四行来自同一组各 3 步的生产 profile；最后一行来自另外采集的每后端 18 步计时中位数，不应把两批执行的差值解释成精确的 CPU 开销。

| 指标 | BS256：原生 → DVM | BS512：原生 → DVM |
|---|---:|---:|
| 全部 GPU kernel 累计耗时 | 2545.928 → 2565.995 ms | 5082.853 → 5131.395 ms |
| 全部 GPU memcpy + memset | 18.059 → 0.290 ms | 35.650 → 0.277 ms |
| GPU 工作之间的空隙 | 2.984 → 2.327 ms | 2.958 → 2.396 ms |
| 首个 GPU 工作开始至最后工作结束 | 2566.971 → 2568.612 ms | 5121.461 → 5134.067 ms |
| 完整 step 中位数，独立计时 | 2565.297 → 2570.352 ms | 5119.240 → 5131.118 ms |

因此，“融合链慢 8%，整步却基本持平”的主要解释有两点：初版遗漏了 DVM 消除的拷贝；融合部分只占整步约 9.5%。GPU 空隙只减少约 0.6 ms，不能用 CPU 提交时间下降几百毫秒直接抵消 GPU 时间增加来解释。CPU 提交与 GPU 执行存在重叠，CUDA API 耗时也可能包含等待设备队列的时间，二者不能相加。

如果**相对当前 DVM，把全部 DVM kernel 的耗时降低 15%**，且其余工作和暴露在关键路径上的 CPU 时间不变，则估算如下。这是基于当前占比的推算，尚未通过修改代码后的完整训练验证。

| Batch size | 当前 DVM kernel / step | 预计节省 | 预计新 step | 相对当前 DVM 的 step 降幅 | 相对原生的 step 降幅 |
|---|---:|---:|---:|---:|---:|
| 256 | 246.596 / 2570.352 ms | 36.989 ms | 2533.363 ms | 1.44% | 1.24% |
| 512 | 487.659 / 5131.118 ms | 73.149 ms | 5057.969 ms | 1.43% | 1.20% |

折算公式为 `step 降幅 ≈ 被优化 GPU 工作耗时 / 当前 step 耗时 × 15%`。如果降低 15% 的对象是整步所有 GPU 工作，包括矩阵乘等未由 DVM 替换的算子，则当前 GPU 几乎连续工作的条件下，step 可接近降低 15%；这与只优化 DVM kernel 的约 1.4% 是不同范围。这里的“优化 15%”指耗时乘以 0.85。

针对 emit 的性能排查，已有两项等价链微基准证据。下面只比较当前 DVM 与改写表达式后的 DVM，两者均无 GPU 拷贝事件，因此不受上述原生拷贝漏计影响。每个变体测量 20 次，交替运行顺序，取 CUPTI kernel 耗时均值。没有修改生产 emitter，也没有据此声称完整训练收益。

| emit 改写 | 链 | BS256 耗时下降 | BS512 耗时下降 |
|---|---|---:|---:|
| `neg(x)` 从 `0-x` 改为 `x*(-1)` | `neg → sum` | 12.64% | 12.30% |
| 同上 | 9 算子 LN 反向链 | 1.39% | 2.13% |
| FP32 `x/8` 改为 `x*0.125` | attention 前向链 | 2.28% | 2.18% |
| 同上 | attention 重计算链 | 2.02% | 1.87% |
| 同上 | attention 反向链 | 13.59% | 13.30% |

`EmitNeg` 当前的 `0-x` 在后端展开成乘以 −1 再加 0，直接乘法可省掉后一条指令。`EmitBinaryScalar` 仍发出标量除法，而相同 BERT 原生除法在 trace 中已使用乘法 kernel。改为精确可表示倒数后，反向链的 VM 指令还消除了一个 `bar(1)` 标记；VM 会为该标记执行 `__syncthreads()`，因此收益不只是除法与乘法的算术差异。上述标量改写只对采样的有限 FP32 输入和除数 8 验证了结果一致，不能直接推广至所有 dtype 和常量。9 算子链的小幅收益有分组波动，尤其是 BS256。

其他性能点需要区分层次：broadcast shape 在 `CanBroadcast` 和 `BroadcastShape` 中重复推导属于 CPU emit 开销，尚未量化；bool 比较与 Select 的类型转换、保存 mask 导致的后端拆分，以及 `mean` 的归约和缩放被拆成两个 kernel，主要涉及 DVM 后端 lowering 和图划分。单改 emit 表达式并不能保证解决后面这些问题。
